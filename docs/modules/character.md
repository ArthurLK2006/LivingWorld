# Contrato — character

Estado: **ainda não implementado.** Este contrato cobre só o estado mínimo do jogador que a Fase 1 usa (LW-035): identidade, posição e orientação. A ficha completa do módulo (habilidades, inventário, corpo, conhecimento — arquitetura 15.4 e 15.6) é visão de fase futura e **não é construída agora**.

- **Responsabilidade:** guardar o estado lógico mínimo de cada personagem controlável (hoje, só o jogador): identidade, posição e orientação; validar pedidos de nascimento e de atualização de posição.
- **Entradas:** comando `request_spawn()`; comando `report_position(actor_id, pos, yaw)`; consulta ao `world` para validar "dentro do mapa".
- **Saídas:** `Result` de cada comando (o de `request_spawn()` também traz o `actor_id` novo, no mesmo padrão de `DecodedSave`/`HeightQuery` já usado em outros contratos — campo extra ao lado de um `Result`); consulta `peek_character(actor_id)` (posição e orientação atuais).
- **Dependências permitidas:** `core`, `world` (consulta de limites do mapa, para recusar posição fora dele). `character` é camada 3; `world` é camada 2 — import permitido (AGENTS cap. 5.1).
- **Dados controlados:** `CharacterState` (posição `Vector3`, orientação `yaw: float`) de cada personagem, guardado num `Dictionary` indexado por `actor_id`. Hoje só uma entrada existe (o jogador), mas o módulo já nasce indexado por ID, e não como um único objeto fixo, para não supor jogador único (AGENTS cap. 6: "nada de 'o jogador' no singular na simulação"; comandos tipados pelo identificador do ator). `Dictionary` com mais de uma entrada no futuro segue a regra de determinismo do `MODELO.md` (visitar por ID, nunca pela ordem natural).
- **Interfaces de comunicação:** `request_spawn()` — **decisão desta tarefa:** sem parâmetro de ator, porque o ID ainda não existe antes do nascimento; o próprio comando gera o ID pelo `core.IdGenerator` (`ctx.ids`, já usado por outros módulos) e o devolve no resultado. `report_position(actor_id, pos: Vector3, yaw: float)` — nome do roadmap, mantido; **observação:** foge do padrão `request_*` para comandos (AGENTS cap. 7); ver "Perguntas para Arthur" no relatório. Recusa posição fora do mapa, consultando `world`. `peek_character(actor_id)`. Nenhum evento nesta tarefa.
- **Testes necessários:** nascer no ponto correto (igual ao `peek_spawn_point()` do `world`, critério do roadmap LW-035); posição fora do mapa é recusada (critério do roadmap); ida e volta de save preserva posição e orientação (critério do roadmap); entra no `state_hash` do `World` (critério do roadmap; LW-022 já garante o mecanismo); `actor_id` desconhecido em `report_position`/`peek_character` devolve erro tratado, sem travar (AGENTS 13.1.4).
